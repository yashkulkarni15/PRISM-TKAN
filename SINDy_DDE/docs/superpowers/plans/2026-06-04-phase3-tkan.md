> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:test-driven-development for every task (write the failing test first, watch it fail, minimal implementation, watch it pass, commit). Steps use checkbox (`- [ ]`) syntax. Each task is a self-contained brief: exact files, the interface contract, representative tests, and acceptance criteria. Implement the FULL unit suite for your module via TDD — the representative tests below are the floor, not the ceiling.

**Goal:** A model-agnostic PyTorch Phase 3 harness with a TKAN model predicting stability severity + trajectory, with first-class XAI, verified end-to-end on synthetic data.

**Architecture:** Data layer → KAN substrate (KANLinear → TKAN cell/encoder, optional sigKAN) → shared trunk + SeverityHead/TrajectoryHead/PhysicsStub → noise-weighted trainer with MLflow + stage-gate → XAI (KAN-native, Captum, SHAP, DiCE) → GL sbatch + keystone E2E.

**Tech Stack:** Python 3.11+ (local 3.13), PyTorch 2.9, numpy/pandas/scipy, mlflow, captum, shap, dice-ml, matplotlib, optional iisignature. Repo uses a `src/` layout (`pip install -e .`), pytest, flat `tests/test_*.py`.

**Execution model:** Phase-gated. Subagents run in parallel WITHIN a wave; a wave must be fully green (its tests pass + integrated) before the next wave starts. Each subagent owns disjoint files — no two agents edit the same file in a wave.

**Branch:** `phase3-tkan`. **COMMIT POLICY: do NOT `git add` / `git commit` / `git push`.** Leave all work in the working tree; the user commits manually when they choose. Ignore every "Commit" step written below.
